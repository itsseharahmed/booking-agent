# Optometry Booking Agent

An AI-powered, multi-location appointment booking system for optometry clinics.

The application will allow patients to search for available appointments, book visits, reschedule or cancel bookings, and ask questions about clinic services through a conversational interface.

The project is being developed incrementally using test-driven development (TDD), with a focus on maintainability, security, and production readiness.

## Getting Started

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/optometry-booking-agent.git
cd optometry-booking-agent
```

Replace `YOUR_USERNAME` with your GitHub username.

### 2. Set up the backend

Navigate to the backend directory:

```bash
cd apps/api
```

Create a Python virtual environment:

```bash
python -m venv .venv
```

Activate it on macOS/Linux:

```bash
source .venv/bin/activate
```

Or on Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
python -m pip install -e ".[dev]"
```

Start the API:

```bash
python -m uvicorn optometry.main:app --reload
```

The API will run at:

- http://127.0.0.1:8000
- Health check: http://127.0.0.1:8000/health
- Swagger documentation: http://127.0.0.1:8000/docs

### 3. Set up the frontend

Open another terminal from the repository root:

```bash
cd apps/web
npm install
npm run dev
```

Open:

http://localhost:5173

## Running Tests

### Backend tests

From `apps/api`:

```bash
python -m pytest -q
```

Run linting:

```bash
python -m ruff check .
```

Check formatting:

```bash
python -m ruff format --check .
```

Check Python types:

```bash
python -m mypy src
```

### Frontend tests

From `apps/web`:

```bash
npm run test
```

Run TypeScript checking:

```bash
npm run typecheck
```

Run linting:

```bash
npm run lint
```

Verify the production build:

```bash
npm run build
```

## Environment Variables

The `.env.example` file documents configuration variables for current and future services.

```dotenv
APP_ENV=development
API_HOST=127.0.0.1
API_PORT=8000

LLM_PROVIDER=groq
GROQ_API_KEY=
GROQ_MODEL=openai/gpt-oss-20b

DATABASE_URL=
REDIS_URL=
```

Groq, PostgreSQL, and Redis are not connected in Increment 1.

Never commit `.env` files containing real credentials or API keys.

## Development Approach

Each increment follows the same process:

1. Define requirements and acceptance criteria.
2. Write failing tests.
3. Implement the feature.
4. Run tests and resolve failures.
5. Refactor the code.
6. Run linting and type checks.
7. Commit the completed increment.

## Security

This project is intended for healthcare-related appointment scheduling.

During development:

- Use synthetic patient information only.
- Never commit credentials or secrets.
- Do not send real patient information to AI providers.
- Keep appointment modifications behind validated backend operations.

Privacy, authentication, authorization, and audit requirements will be implemented and tested in later increments before any production deployment.
